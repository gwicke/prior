# rig 0.45.0 dependency notes

prior now depends on the crates.io `rig-core` / `rig-agent` / `rig-reqwest`
**0.45.0** (the gwicke/rig git pin is gone). This file records what the new
surface forced and which of prior's assumptions now live in one place, so a
future bump starts from the seams rather than from the compiler.

Status: migrated; `cargo build`, `cargo clippy --all-targets`, and the full test
suite (unit, pty/e2e, mock-SSE) pass. The upstream guide
(`https://raw.githubusercontent.com/0xPlaygrounds/rig/v0.45.0/MIGRATING.md`)
stops at 0.44, so the 0.45 shapes were read off the crate sources.

## Cargo

- `rig-core` needs the `reqwest` feature: it is what gives the concrete clients
  their `from_env()` / `client()` constructors on `rig_reqwest::shared()`.
- `rig-reqwest` 0.45 has no `DefaultTransportBuilder` / `DefaultTransportClient`;
  the shared client is `rig_reqwest::shared()`.
- New transitive crates: `rig-http`, `rig-memory`, `rig-tungstenite`,
  `rig-derive`. `rig-run` is gone (folded back into `rig-agent`/`rig-core`).

## Message model

- `Message::Assistant(AssistantMessage)` replaces the `{ id, content }` struct
  variant. `AssistantMessage` is non-exhaustive and carries `origin`, whose
  `response_id` is pi's `responseId`. `src/agent/transcript.rs` owns the mapping:
  `assistant_message(response_id, content)` stamps an `Origin` tagged "prior"
  (`None` id = an aborted turn, as before), and `response_id(turn)` reads it
  back. Everything that touched `Message::Assistant { .. }` goes through
  `assistant_content(msg)`.
- `Reasoning` is `{ text, redacted, native }`; `ReasoningContent` is gone.
  Provider data (the thinking signature) lives in `native`, whose
  `{"type":"thinking","thinking":…,"signature":…}` item is exactly the shape
  Anthropic decodes and replays. The pi JSONL round-trip stores
  `thinkingSignature` and rebuilds `native` from it on load
  (`session.rs::pi_content_to_assistant_content`). Whatever else `native` holds
  is *not* persisted: redacted reasoning survives as its text only.
- `ToolCallId` → `CallId` (`wire()`/`Display` for the wire string,
  `CallId::from_wire` to mint one). `ToolCall` keeps `{ id, function, native }`;
  `ToolFunction.arguments` is a `Map`, read as `arguments_value()` /
  `arguments_json()` and rebuilt with `ToolFunction::new(name, value)`.
  `ToolResult` gained `is_error` and lost `provider`.
- `ToolName` is a validated newtype; `transcript::tool_name(&str)` clamps the
  impossible-empty case.

## Prompt / stream / errors

- One error type: `PromptError`. `StreamingError` and `CompletionError` are
  gone. `errors.rs` classifies `PromptError::{Provider, Report, MaxTurns,
  UnknownToolCall, Cancelled}`.
- **Relayed failures arrive as `PromptError::Report(ErrorReport)`**, not as a
  `ProviderError`. The report carries `http_status`, headers and body, so
  `classify_report` reuses `classify_status` with `classify_provider_error`.
  Without this a 429 escaped classification as `Other` and lost the retry
  budget (`tests/compaction_esc.rs` pins it).
- Streaming items are `Item<StreamEvent>`: text and reasoning arrive as
  **fragments** (`StreamEvent::{Text, Reasoning}`), and the finalized block
  comes in `StreamEvent::End`. `turn.rs` paints/accumulates fragments only and
  lets the turn hook (`on_model_turn_finished`) own the transcript.
- `PromptResponse.output()` is a method; `messages` is a plain `Vec<Message>`.
- `Usage` counters are `Option<u64>`; `is_reported()` gates the update, and an
  unreported counter contributes 0 to prior's session totals.
- `agent.stream_prompt(p)` → `agent.prompt(p).stream()`.

## Providers and hooks

- Concrete clients replace the generic `Client<Ext, H>` + `AgentClient` trait:
  `AgentBuilder::new(client.completion(model))`.
- Provider matrix (`src/agent/build.rs`): free `vendor::from_env()` for the
  OpenAI-shaped vendors, `Anthropic::from_env()` / `OpenAI::from_env()` /
  `Cohere::from_env()` / `Gemini::from_env()` / `Ollama::from_env()` for the
  primary clients, `zai::anthropic_from_env()` for Z.AI's Messages endpoint.
- **llama.cpp** is built directly: 0.45's `from_env` insists on
  `LLAMACPP_API_KEY`, but a local server needs none. `llamacpp_base_url` adds
  `/v1` unless the override already ends with it, matching what the old
  provider did with a bare `http://host:port`.
- **ChatGPT / Copilot OAuth** is `SignedInModel` over `rig_core::catalog`
  (there is no client with an OAuth mode). `signed_in_builder` resolves the
  model's spec, or synthesizes one (`ModelSpec::new(provider, id).with_tools`)
  when prior serves an id rig's catalog does not list — Copilot's default
  `gpt-5-codex` is one. The credential is a per-request `Authenticator`, so a
  long session outlives one access token.
  - `GITHUB_COPILOT_API_KEY` is a Copilot *session* token → `OpenAIConfig`
    directly (honouring `GITHUB_COPILOT_API_BASE`/`COPILOT_BASE_URL`, which
    `with_key` does not read).
  - `COPILOT_GITHUB_ACCESS_TOKEN` is a GitHub token →
    `AuthSource::GitHubAccessToken`, which rig exchanges and refreshes.
- Tools: `rig_core::rig_tool` (was `tool_macro`); parameter docs move into
  `params(name = "…")` (rustc rejects doc comments on parameters). Host-only
  tool metadata is now a `ContextValue`, so `EditResolutions` derives
  `Serialize`/`Deserialize` and names its key.
- Hooks: `on_completion_call` (history patch), `on_dispatch` (paint the call,
  cancel), `on_outcome` (paint the result, record edit anchors, rewrite the
  model-facing result), `on_model_turn_finished` (transcript + logging),
  `on_invalid_tool_call` (retry with the tool list). `on_outcome`'s
  `rewrite_tool_result` replaces the model-visible output only; the result the
  `ToolResult` stream item carries (which prior persists) is the rewritten one.
- Prompt caching: Anthropic gets `with_prompt_caching()` plus a run-level
  `CacheRetention::Long`, which is the 1-hour moving breakpoint the fork's
  `with_automatic_caching_1h()` produced. Z.AI's Anthropic endpoint caches
  implicitly (rig's Z.AI dialect refuses a long retention), so it is built bare.
- `accept_unknown_finish_reasons(true)`: 0.45 fails a run on a finish reason
  outside its vocabulary; the fork's `FinishReason::Other` was a normal stop
  (`empty_turn_with_unmodeled_finish_reason_still_finalizes`).

## Known gaps / future work

- **OpenRouter / Z.AI prompt-cache breakpoints are gone.** The fork's
  `with_prompt_caching()` put `cache_control` on the system prompt and last
  message; 0.45's OpenAI family has no equivalent (its cache option is OpenAI's
  `prompt_cache_retention`). Emulating it would mean rewriting message content,
  which `Text` has no `additional_params` for. Automatic caching still applies
  where the provider does it.
- **OAuth sign-in ignores the custom base-URL env vars**
  (`GITHUB_COPILOT_API_BASE`, `CHATGPT_API_BASE`): `SignedInModel` builds its own
  `ConnectOptions`. The non-OAuth Copilot path does honour them.
- **Pre-existing env-name drift** (not caused by this bump): prior gates on
  `AZURE_OPENAI_API_KEY`/`AZURE_OPENAI_ENDPOINT`, `HF_TOKEN`, and
  `GOOGLE_API_KEY`, while rig reads `AZURE_API_KEY`/`AZURE_ENDPOINT`,
  `HUGGINGFACE_API_KEY`, and `GEMINI_API_KEY`. Setting only prior's names fails
  in `from_env`. Fix by accepting both and bridging, if it matters.
- **Redacted reasoning** persists as its text, not the encrypted payload.
- `Usage` under-reporting: a provider that omits a counter now adds 0 to the
  session total rather than being treated as an error.
