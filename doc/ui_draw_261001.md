## Drawing algorithm: Outline & efficiency plan
NOTE: Keep this document tightly focused on the design. No extended prose.
Follow-ups as short bullet points only.

Model: 
- Regular stdout writes for content
- moving "fold", divider between ui / menu frame at bottom of screen and
  content scrollback (top of screen). Moves down with content emission. Gets
  pushed back up for taller UI menus.
- drawing: mix of stdout and raw mode. no alternate screen.
- content owns its rows (closed lines, full-width when styled)
- Seam: normalization stays — content always arrives at line start; the UI
  emits only the gap, never a closing newline, never derives position from
  content's trailing newline.
- Gap is a painted row (full width, in the frame), not emitted LFs.
- Append regime: caret == term_h is the switch. diff/erase act only on rows
  that hold prior frame content — never content rows, never empty rows.
- diff reach: only while the frame position is unchanged — no content rows
  since the last paint (status/menu/editor/caret updates). Content consumes
  the frame rows; everything below is then rewritten in full at the shifted
  position (paint-forward). Zero-row content writes don't move the frame:
  don't consume when rows == 0. A pure shift of rows above the append is
  anchor bookkeeping only (top -= scroll), never a repaint — and in the
  append regime a content write still rewrites the frame, because the seam
  always moves further than the scroll catches it (k < n for h >= 1), so
  every frame slot's content comparison fails.
- Frame growth at the bottom: append (scroll content up); the frame never
  paints over content rows.
- Budget/windowing stays: scrollback at top of screen, frame/menu gets at most
  ~2/3 of the vertical space; budget + scroll within that.
- The absolute entry point — first paint, foreign writer, resize: reanchor +
  DSR stays the only sanctioned absolute, everything else relative.

- Limit clearing:
  - Overwrite only if frame height did not change, or if it increased. No
    clearing, only ovewriting (we usually write full-width rows with
    background color).
  - Only clear rows below frame if 
    `old_frame_height - new_frame_height - content_rows_written > 0`, so if
    old rows are not overwritten anyway, and the fold is now not at the
    bottom-most possible position. Do this clearing *at the end* of the
    regular output pass, to minimize flickering in new content.
- Raw mode writes vs. stdout append: When reaching the bottom of the term in
  the downward pass, switch to regular stdout writes, so that earlier content
  gets pushed up.
- Caret-only moves: When only the caret moves (no row changes), is a
  caret-only emit worth a special case, or is it subsumed by the diff (both
  cheap)?
