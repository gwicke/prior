## Drawing algorithm: Outline & efficiency plan

NOTE: Keep this document tightly focused on the design. No extended prose.
Follow-ups as short bullet points only.

Model:

- Regular stdout writes for content
- moving "fold", divider between ui / menu frame at bottom of screen and
  content scrollback (top of screen). Moves down with content emission. Gets
  pushed back up for taller UI menus.
- drawing: mix of stdout and raw mode. no alternate screen.
- content owns its rows (closed lines, full-width when styled)
- Seam: normalization stays — content always arrives at line start; the UI
  emits only the gap, never a closing newline, never derives position from
  content's trailing newline.
- Gap is a painted row (full width, in the frame), not emitted LFs.
- Append regime: caret == term_h is the switch. Erase acts only on rows that
  hold prior frame content — never content rows, never empty rows. Diff is
  byte-driven per eligibility below.
- diff reach: only if no content rows since the last paint (status/menu/
  editor/caret updates), and only for rows that are not appended (frame
  growth). Zero-row content writes don't move the frame: don't consume when
  rows == 0.
- diff eligibility: byte comparison (expected vs screen), not position —
  shifted rows stay eligible (a shift leaves old bytes unmodified: match vs
  partial update is the diff's call). Expected bytes: frame composition =
  draw-cache, content rows = ReplayUnits (the width-change replay's source).
  A shift alone is anchor bookkeeping (top -= scroll), never a repaint
  trigger. Rows above the seam match in the steady state via the
  overwriting invariant (paint goes strictly downward from the seam; old
  frame rows sit below the old seam, so content/paint overwrites each before
  a scroll lifts it) — matched, not exempt: width-change remnants / foreign
  writes are where they stop matching.
- Content append consumes the frame rows; everything below is rewritten in
  full at the shifted position (paint-forward) — in the append regime too:
  the seam moves further than the scroll catches it (`k < n for h >= 1`), so
  every frame slot's comparison fails.
- Frame growth at the bottom: append (scroll content up); the frame never
  paints over content rows.
- Budget/windowing stays: scrollback at top of screen, frame/menu gets at most
  ~2/3 of the vertical space; budget + scroll within that.
- The absolute entry point — first paint, foreign writer, resize: reanchor +
  DSR stays the only sanctioned absolute, everything else relative.
- DSR is for exceptional events only (startup, resume, resize, $EDITOR
  return, error/dialog entries) — never in regular drawing; the read_input
  entry query is startup-only (ENTRY_DSR_DONE), and a silent DSR is no new
  information: an intact frame stands (keep live, park to its caret).
- Erase/overwrite — one pass, no separate clearing pass:
  - Consumed rows: overwrite only, no erase walk. Each line is rewritten
    with a line clear (`\x1b[K`) emitted on entry (at col 0: right after a
    newline, or at write start) — content and frame alike. Never mid-line
    (wrap-pending: EL at the last cell would eat it).
  - Every terminal row a content line occupies must be **entered by a
    byte**: a natural wrap crosses rows with no byte between them, so
    `LineClear` never arms and the continuation row keeps the frame's
    cells — the committed-prompt right-margin remnant. Two guards, one
    per layer: the renderer wraps at the source (word/punct breaks, +2
    continuations — codewandler 738e12a), and `with_content_writer`'s
    `WrapLines` is the choke net underneath (cell-exact only, below the
    hold / above the counter and the line-clear) so nothing over-wide
    can reach the terminal. Rows don't move: `rows_of` counts a wrap and
    a `\n` alike (pinned); escapes are never split, colors ride the
    terminal's SGR state across the break.
  - Frame full paint: `EL + padded row` per row in the same forward pass.
  - Erase rows below the frame no longer covered (they held the previous
    frame): still needed, but appended to the same pass — only when
    `old_h - new_h - content_rows_written > 0`, after the frame rows,
    before the caret - and only that number of rows.
  - Height unchanged / no content: diff — overwrite only rows that differ;
    no full-line clear in diff mode (padded rows overwrite; short rows keep
    the existing tail `el_if_short`).
- Raw mode writes vs. stdout append: When reaching the bottom of the term in
  the downward pass, switch to regular stdout writes, so that earlier content
  gets pushed up.
- Caret-only moves — settled: subsumed by the diff. Nothing painted leaves
  the cursor at the old caret, so a steady caret writes zero bytes and a
  moved one writes only its relative walk (`CR` + `CUF`); pinned by
  `identical_apply_with_a_steady_caret_emits_nothing` and
  `caret_only_change_walks_without_row_bytes`.
