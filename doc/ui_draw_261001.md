## Drawing algorithm: Outline & efficiency plan
Model: 
- Regular stdout writes for content
- moving "fold", divider between ui / menu frame at bottom of screen and
  content scrollback (top of screen). Moves down with content emission. Gets
  pushed back up for taller UI menus.
- drawing: mix of stdout and raw mode. no alternate screen.

- Limit clearing:
  - Overwrite only if frame height did not change, or if it increased. No
    clearing, only ovewriting (we usually write full-width rows with
    background color).
  - Only clear rows below frame if 
    `old_frame_height - new_frame_height - content_rows_written > 0`, so if
    old rows are not overwritten anyway, and the fold is now not at the
    bottom-most possible position. Do this clearing *at the end* of the
    regular output pass, to minimize flickering in new content.
- Caret-only moves: When only the caret moves (no row changes), is a
  caret-only emit worth a special case, or is it subsumed by the diff (both
  cheap)?
- Raw mode writes vs. stdout append: When reaching the bottom of the term in
  the downward pass, switch to regular stdout writes, so that earlier content
  gets pushed up.
